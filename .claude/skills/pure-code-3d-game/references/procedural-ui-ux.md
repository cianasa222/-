# Commercial-quality procedural game UI/UX
Reference source: https://www.gameuidatabase.com/ (design research only; no assumption of asset reuse permission or API access). If site inaccessible, use legally available public reference or original screenshots. Do not bypass site access controls, bulk scrape, redistribute images or copy protected distinctive designs. No reference images bundled as runtime assets.
Research 3-5 relevant games per major interface where accessible, not a generic website template. Record source URL/title, screen type, input/platform, observable layout and interaction patterns, design rationale, accessibility, what to avoid; distinguish observed and inferred behavior. Extract original design system: normalized anchors/safe areas/grid, typography scale (licensed fonts or procedural glyphs under project policy), spacing, color contrast, opacity, geometry/radius/strokes, hierarchy, icon grammar, animation duration/easing/spring, feedback and audio. Avoid reproducing brand marks, game-specific art and unique iconography.
Implement with code: SVG paths and procedural geometry, CSS/Canvas/native UI, shaders for material and masks, interpolation/finite-state machines; seeded procedural texture only. Separate view from game state and commands. Reusable components: HUD, inventory/equipment, skill tree, map/minimap, menus, settings, modal, tooltip, quest, damage/status, accessibility and navigation. Build only relevant components.
Define state contract: idle/hover/focus/pressed/selected/disabled/loading/error/empty/overflow, controller and touch navigation, key remap, safe-area and localization/long text, dynamic resolution, UI scale, focus restoration, pause semantics. Use scalable anchors and responsive layout; keep readable contrast and redundant non-color cues; respect reduced-motion setting. Test click/touch/controller, focus traversal, no click-through, text clipping, performance and actual screenshots on supported aspect ratios. Reference is design evidence, not acceptance.
Use UI token JSON + component state map + screenshot matrix + input replay; visual comparisons of actual target builds; no generic web-dashboard appearance unless intended. Report UI_PENDING when target screenshots/interaction evidence missing.
