# Profile-first performance / fast-anything
Upstream: https://github.com/EL4CTEO/fast-anything (MIT). Official skill and license in integrations/fast-anything. Use on representative Node/Bun/Deno or native workloads, not on browser GPU shaders. Node integration upstream uses native bindings, not browser WASM.
1. Freeze commit, hardware/driver/browser, seed, input replay, graphics settings, resolution, warmup and workload. Capture CPU/GPU frame time separately, p50/p95/p99, memory, allocation/GC, draw calls, shader compilation and transfer cost. Target 60fps = 16.67 ms or project budget; record worst scene. Do not fabricate metrics.
2. Fix algorithms/data layouts and redundant work first: spatial indexing, SoA, batching, dirty updates, caching with regenerable seed, LOD and GPU instancing. Rank hot paths by inclusive time and portability; prioritize meaningful end-to-end savings, not tiny functions. Use Amdahl's law to bound benefit.
3. Pure deterministic CPU kernel: stable typed API, JS reference retained, Rust native or WASM adapter (browser), batch calls across boundary, no per-entity FFI or unnecessary copies. GPU-parallel work stays WGSL/compute where justified. Keep renderer, UI, state management in existing stack; no automatic engine replacement.
4. Use recorded inputs plus seeded fuzz, empty/max, NaN/Inf/-0 where legal, Unicode, errors, overflow, ordering, collision/contact edge cases and deterministic replay. Specify tolerances per domain before testing; compare reference output and game-state invariants. Never alter fixtures to pass.
5. Benchmark warm and cold, interleave A/B runs with fixed workload, include FFI, memory transfer, initialization, p95/p99 and power/thermal effects on target device. Approve only if semantic tests pass and project budget improves without visual/quality regression. No claim of universal speedup.
6. Feature flag + original path + rollback test. Keep implementation/source, tool versions, logs, before/after metrics and decision in evidence. Do not enable merely because a microbenchmark improves. Unavailable target environment => PERF_PENDING.
Optional upstream setup in supported shell: pin reviewed package version of @el4cteo/fast-anything or cargo crate; install Rust toolchain; run fast-anything doctor, scan -- <representative command>, port <id>, verify <id>, enable <id>, bench, report; disable <id> or FAST_ANYTHING_DISABLE=1 for rollback. Do not install automatically from an unreviewed mutable source. Browser fallback: browser profiler + project-specific WASM harness. Upstream commands and exact flags checked with installed --help.
