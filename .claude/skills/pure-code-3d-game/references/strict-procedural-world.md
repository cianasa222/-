# 严格程序化世界契约 · Strict Procedural World v1

> 本文件是 `pure-code-3d-game` v4.1 起的 **code-only 项目默认硬约束**。用户明确要求的目标：世界中任何可见、可听、可交互的对象都必须能够以代码 + 数学公式 + 参数 + Seed + 时间输入重新生成。包括一根眉毛、一缕头发、一粒雪花、一个脚步和一次碰撞。**代码量不是优化指标；结果质量、复现性、性能、授权正确性才是**。
>
> 与 v4 通用 GameKit 兼容：当且仅当用户明确批准使用外部素材时，另行采用 `hybrid` 项目配置；不得因为数学方案难写、模型不美观或 AI 能力不足而自行把 code-only 切成 hybrid。
>
> **v4.2 修正声明（2026-11-24）：** 本文件 §2 表格中“眉毛 / 头发 / 眼睫毛”“眼 / 眼睑 / 牙齿 / 嘴唇”两行与 §3“逼真五官至少需要……”一段，对 3D 英雄人物**不再适用**。实测结论：逐根眉毛/睫毛与完整面部建模是“橡皮人”问题的帮凶，不是解法；默认英雄人物藏脸藏手（头盔 + 雪镜 + 面罩 + 手套），不建模眼球/鼻子/嘴唇/眉毛/睫毛。需要露脸的项目须先过“像人”验收门并经用户明确批准，另立专项。上述两行两段仅保留为“露脸专项”的参考，不再是默认要求；与 references/sdf-character-method.md 冲突时以该方法文档为准。

## 1. 可审计的「纯代码」定义

生产运行时不得依赖、分发或把下列结果伪装成代码：外部 GLB/FBX/OBJ、贴图/图集、录音/音频采样、影片、预录 BVH 动作、逐帧关节曲线、压缩过的模型顶点数组、手工雕刻的人脸导出文件、SVG 素材图片或 Base64 内嵌同等资产。**预计算数据换成 JSON、编码到 JS 或烘成 SVG 不改变其来源**。可写少量用于生成的控制点、参数表和物理/色彩常量，但每项都必须是生成规则的输入，而非密集采样后的结果。

允许：原创或许可合规的数学算法源码、WebGPU/WebGL2 着色器、由公式生成的三角形、通过函数采样的材质/法线/颜色场、由接触约束求解的动作、程序化 Web Audio 合成、程序计算的 SVG path/Canvas 素描、Seed 生成的天气/生态/剧情规则。允许离线用外部应用检查数值、对比参考、可视化曲线；**不得在交付包中偷偷放入那些工具导出的素材数据**。在线游戏允许账户/联网玩法所需的网络请求；禁止借此从 CDN 偷载美术资源。

运行时缓存 CPU/GPU 生成结果是合规的：缓存必须能删掉后由相同 Generator 版本、配置、Seed 和确定性时间重新算出来。打包阶段在本地临时烘焙进行性能分析也合规；**打包产物不得依赖离线烘焙的模型/动画/贴图作为正式艺术来源**。高画质不要求在每帧重新算完所有几何：静态面/程序法线可以初始化一次，粒子可 GPU 实例化，连续动作只求当帧关节姿态。真正优化目标是删除冗余计算、共享函数和跨设备 LOD，而非牺牲真实性。

## 2. 一切可回溯到生成器

| 世界对象 | 唯一可信输入 | 程序化输出与可验收指标 |
| --- | --- | --- |
| 人体 / 角色 / 脸部 | 身高与面部设计比例、骨长、五官标记、风格参数 | 分层 Loft / SDF / 隐式曲面与局部硬表面；顶点/索引/法线有效、轮廓/对称与艺术审核 |
| **眉毛 / 头发 / 眼睫毛** | 根部曲线、毛流方向、长度、曲率、粗细分布、Seed | 3D 曲线扫掠、可见性驱动的带状发束或 Shader 纤维；**无预制毛发贴图**、分镜/LOD 验收 |
| 眼 / 眼睑 / 牙齿 / 嘴唇 | 眼球半径、虹膜程序图案、上下眼睑曲线、咬合/唇形参数 | 球面/曲面+布光+程序虹膜/眼睑/牙齿几何；视线与眨眼/表情状态可变 |
| 身体骨架与皮肤 | 语义骨名、绑定姿势、解剖/风格尺寸、关节约束 | 骨骼层级和蒙皮权重按部位生成；无预制 T-pose 网格 |
| 动画 | 根运动速度、步长、支撑/摆动相位、动作意图、碰撞目标 | 关节运动学/IK、接地/步态/混合、事件时间标记；固定输入可复现 |
| 地面 / 山雪 / 水 / 建筑 | 高度函数、噪声、样条、语法规则、材料参数 | 程序拓扑、表面法线、贴图函数、距离 LOD；物理和渲染统一查询 |
| 每片雪花 / 雾 / 飞尘 | Seed、flakeId、时间、气流与力场 | 独立确定性轨迹、六折对称晶形及光照；GPU 大规模并行 |
| 树叶 / 碎屑 / 火花 | 分支语法、概率场、方向、生命周期 | 按实体 ID 可复现生成，池化/实例化且不影响玩法规则 |
| 声音 / 音乐 | 事件、频率、包络、谐波、噪声种子、谱与节奏参数 | Web Audio 合成、音量限制器、并发语音预算；无音频采样文件 |

**重要：** 几何/运动参数的来源要可解释。可用开放论文和公开标准 *作为公式和限值的参考*，但不能从中复制未经许可的整套网格或动作数据；“平均腿长 0.5×身高”这种近似只能标为 `design-hypothesis`，不能包装成实测人体标准。

## 3. SVG 与 3D 的正确关系

SVG 的 Bézier 曲线、路径拼接、轮廓布尔运算和动画插值是非常适合 **眉毛/眼睑/嘴唇轮廓、服装版型、UI、2D/2.5D 游戏** 的数学工具。3D 人脸不能仅在球前贴一张 SVG 五官就宣称建成。可用 SVG path 所代表的数学曲线生成曲面扫描、边缘倒角、厚度、法线和真正的三维眉骨/眼睑；也可由相同参数导出 SVG 验收图。SVG 在这里是**方程的表达形式**，不是预先画好的图片资产。

逼真五官至少需要：骨面体积/脂肪、眼窝深度、上下睑与角膜空间关系、鼻翼/嘴唇/耳部局部形体、肌肤分层散射与油光、毛发方向性、表情/眨眼时的变形与接触。不要依赖一个模糊 SDF 合并所有部件，避免橡皮泥质感；也不以方块、无厚度平面或静态高光冒充真实结构。

## 4. 视觉质量优先的程序化预算

- 模型由 CPU 初始化时计算一次，再上传 GPU；重复场景装饰使用 Instancing 或基于 Seed 的 instance id。可缓存编译、网格和程序纹理，但缓存不是版权/资产来源。
- 雪、植被、细砂、毛孔等高重复细节优先在 GPU vertex/fragment/compute（平台支持时）求值；低端 WebGL2 使用 shader+instancing 退化，不在 JS 中逐粒创建对象。
- 先做物体屏幕占用测量：不足 1px 的毛发由过滤的材质/法线贡献，主轮廓发束保持几何；近景增细节而不是给所有远景同等网格。
- 画质低档可以削减不影响玩法的粒子数量、阴影精度、次级材质细节；**不能偷偷把精细程序化角色降级成方块人，不能改变危险预警范围与逻辑**。
- 每个产物的质量判断要在角色 Lab/正式机位真实出图。阴影、法线、边缘、动态接地、人体比例、面部表情应有固定 Seed/时间/机位的对照证据。30 次无效调参不能自动等于艺术通过。

## 5. 严格的 AI 任务门禁

每个 `code-only` AI 任务必须声明：`generatorId`、`generatorVersion`、`inputSchema`、`seedDomain`、`measurementOrDesignProvenance`、`allowedPaths`、`forbiddenPaths`、`renderTarget`、`fixedReplay`、`performanceTarget`。变更模块接口需独立批准。不允许代理在代码里私自 `fetch('hero.glb')`、下载贴图、塞 Base64、手写万行顶点数组或抄外部动作帧来绕过任务。

运行 `node tools/procedural-gate.mjs <project-dir>` 检测常见非法资源、预烘焙大数组、生产目录中的非 Seed 随机源。它是**静态预检**；并不能证明每条曲线是数学生成，也不能证明艺术质量或授权。CI 必须同时审计打包结果及浏览器 network trace，执行 Seed 重建、GPU 截图/视频、动作回放和性能日志，不可只凭静态 `PASS` 宣告合格。

## 6. 状态与边界

本轮自带的 `tools/procedural-core.mjs` 是**最小可执行数学组件**：确定性噪声/fBM、生成网格的 Bézier 扫掠、头部体积、独立眉毛、骨架参考、两骨 IK、接地步态、雪花场与合成冲击波形。它不能自动完成真实级人脸、完整蒙皮和布料，也没有经过真实 WebGPU/WebGL2 光栅化、iPhone 性能或美术验收。正确状态是 `ALGORITHM_TESTED / VISUAL_PENDING`。
