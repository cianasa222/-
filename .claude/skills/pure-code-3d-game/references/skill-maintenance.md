# Skill quality / upkeep
Keep quality floor separate from project taste. Floor: valid geometry, meaningful input, no clipping/illegal assets, stable replay, accurate performance evidence. Taste: art direction, face, camera, color, typography, motion rhythm; derive from brief, not hardcode one game's style. Store project brief/recipes/design tokens and user-approved preferences separately; only measure what can be measured.
Progressive disclosure: CURRENT → MODULES → SKILL + core constraints → only relevant module files → specific upstream docs if needed. Bundle is offline fallback, not mandatory read. Router deduplicates dependencies and rejects missing module IDs/cycles. Module additions must update triggers, dependencies, references, source license, tests, version and evidence. Track upstream commit/version and API compatibility; validate with actual installed CLI help on host. Do not automatically upgrade or run arbitrary hooks. On version changes compare upstream APIs, lint links (including upstream reference gaps), re-run tests for changed code, record prior vs current test results. Preserve immutable release and dual sync.
