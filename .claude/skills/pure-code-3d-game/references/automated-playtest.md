# PlaytestKit / CaptureKit
Use real game runtime, not parallel QA stubs. Set 3–5 blocking invariants, real player input, seed, milestones, expected observations, and viewport/device. Run existing GameKit checks, actual compiler, asset audit; deterministic simulations only when actual rules support them. For native engines emit equivalent evidence from actual runtime.
Expose development-only window.__gamekitRuntime (or __omGame) with getState/getStats/sendAction/runSelfTests. State serializable with phase; self-test map {contact:{pass:true,detail:'...'}}. Do not expose privileged hooks publicly.
Optional Node runner tools/browser-playtest.mjs uses operator-installed compatible puppeteer-core and Chrome, local server only. Example config:
```json
{"url":"http://127.0.0.1:8080","executablePath":"/path/to/chrome","outputDir":"evidence/playtest","steps":[{"type":"click","selector":"#start"},{"type":"key","key":"ArrowRight"},{"type":"burst","count":4,"intervalMs":100}]}
```
Run node tools/browser-playtest.mjs config.json. Supports key/click/tap/action/wait/screenshot/burst, two default viewports; override and test physical inputs individually. Waits for hook and not-loading before steps, checks self-tests, layout, console/network errors; blocks external origins and records failures. Compare before/after state against intended outcomes; synthetic actions are not real input. Use fixed scene/seed/camera and several motion phases, assess material/light, silhouette, camera clips, readable telegraphs, motion/contact, UI. Save evidence with actual revision, device and config. Screenshots/video are QA, not runtime art. 
Runner source implemented, actual Chrome execution pending; no browser package or engine bundled. Native/multiplayer adapters, video export, automated cover cropping and richer budgets remain extensions. Functional headless evidence never substitutes for real GPU/device/thermal/input latency, audible review or visual signoff. Do not mark ready if blocking checks fail.
